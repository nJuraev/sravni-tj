## Стек

| Компонент | Технология | Назначение |
|---|---|---|
| Парсер | **Go** (3 бинарника: `discover`, `parser`, `rates`) | Сбор продуктов и курсов валют с сайтов банков по крону |
| Бэкенд | **PHP / Laravel 13** (PHP 8.4) | REST API, приём заявок, admin API, Telegram-бот (вебхук) |
| Фронтенд | **Vue.js** + Pinia + Vue I18n, **SSR** (Express) | Витрина сравнения, фильтры, калькулятор, формы заявок, `/profile`, `/admin` (CSR) |
| БД | **PostgreSQL** | Общее хранилище: продукты, банки, заявки, курсы, тг-подписки |
| AI для парсинга | OpenRouter (дефолт в проде — `deepseek/deepseek-chat-v3.1:free`), прямые gemini/qwen/deepseek как альтернатива | Извлечение структурированных данных из Markdown |
| Скрейпер | `direct` (HTTP+readability, дефолт), Firecrawl, свой headless Chrome/CDP — per-source выбор | HTML страницы банка → Markdown/DOM |
| Инфраструктура | docker-compose | Локальный запуск всех сервисов |

**Поток данных:** парсер (Go) пишет напрямую в PostgreSQL → Laravel читает из той же БД и отдаёт через REST API → Vue рендерит витрину (SSR для публичных страниц). Курсы валют — отдельный пайплайн (свой бинарник, свой почасовой cron), независимый от кредитов/депозитов; после прогона триггерит рассылку алертов подписчикам Telegram-бота.

## Структура (монорепо)

```
sravni-tj/
├── parser/            # Go — парсер продуктов (cron)
├── backend/           # PHP / Laravel — REST API + приём заявок + admin API (/api/admin)
├── frontend/          # Vue.js — витрина сравнения + формы заявок + админка (/admin)
└── docker-compose.yml
```

Админка живёт внутри backend/frontend (отдельных директорий нет): API под `/api/admin/*`, UI под маршрутом `/admin`.

### Ключевые таблицы PostgreSQL

- **`banks`** — банки: `name_ru`, `name_tg`, `slug`, `status` (active/inactive), `is_partner`, `contact_email`, `website`, `phone`, `address_ru/tg`, `about_ru/tg`.
- **`bank_source_urls`** — URL для парсинга, привязанные к банку и категории (`credit`/`deposit`/`installment`); один банк может иметь несколько URL (мультидоменность); своё поле `email` для доставки лида. Управляются прямым UPDATE в БД без деплоя.
- **`bank_parse_instructions`** — инструкции парсеру per-банк: `start_url`, `menu_sections`, `css_hints`, `rate_rule` (json_path для детерминированного парсинга курсов без AI), `scraper`.
- **`products`** — продукты: `category`/`subcategory`, мультиязычные `name_ru`/`name_tg`, `status` (active/draft/hidden/outdated), `currency` (TJS/USD/EUR), диапазоны ставки/суммы/срока, `features` (jsonb), `locked_fields` (поля, зафиксированные редактором в админке — парсер их не перезаписывает).
- **`product_rates`** — тарифная сетка продукта (term/amount/rate), источник истины для агрегатов `products.rate_min/max`.
- **`leads`** — заявки: `full_name`, `phone`, `consent` (обязателен `true`), привязка к продукту и банку.
- **`bank_reviews`** — отзывы о банке: `rating` (1–5), `body`, `consent`, `status` (pending/approved/rejected) — премодерация только через прямой доступ к БД.
- **`bank_currency_rates`** — курсы валют банка: `currency`, `category` (cash/transfer), `buy`/`sell`, `rate_date`.
- **`users`** — публичные пользователи: `telegram_id`, `telegram_username`, `phone`, `api_token`; `email`/`password` nullable — регистрация только через Telegram-бота.
- **`rate_alert_subscriptions`** — подписки на алерты по курсу: `user_id`, `currency`, `op` (buy/sell), `direction` (above/below), `threshold`.
- **`parser_runs`** — метаданные парсинга (только при флаге `PARSER_DEBUG_LOG=true`).
- **`admin_users`** — пользователи админ-панели: `name`, `email`, `password`, `role` (admin/editor), `is_active`, `api_token`.

## Ключевые правила и инварианты

- **Мультиязычность:** интерфейс и данные на двух языках — `ru` и `tg`. Поля хранятся парами `*_ru` / `*_tg`.
- **Мультивалютность:** TJS, USD, EUR. Ставка зависит от срока, суммы и валюты — это многоуровневые тарифные сетки, не одно число.
- **Заявки:** `consent = true` обязателен, иначе `POST /api/leads` → 422. Заявка всегда уходит на email банка (`banks.email`), независимо от `is_partner`.
- **Парсер:** AI вызывается в режиме structured output; числовые поля валидируются на диапазон (ставка 0–100%, сумма > 0) до записи в БД (анти-галлюцинации).
- **API отдаёт** только продукты со `status = active` и банком `status = active`.
- **Калькулятор** считается полностью на клиенте (аннуитет для кредита, простые/сложные проценты для депозита) — не парсится.
- **Без классической авторизации** на витрине для анонимных посетителей (заявки анонимны, без логина/пароля). Управление данными продуктов/банков — через **админ-панель** (`/admin`) либо прямой доступ к БД.
- **Админка:** аутентификация через таблицу `admin_users` (встроенный token-guard Laravel, guard `admin`, токен в `Authorization: Bearer`). Роль `admin` управляет пользователями; `editor` — без раздела пользователей. CRUD по банкам/продуктам пишет в guarded-модели через `forceFill`.
- **Telegram-бот и `/profile`:** единственный публичный "аккаунт" — регистрация только через `/start` в боте (создаёт `users.telegram_id` + `api_token`), без email/пароля. `/profile` на витрине управляет подписками на алерты по курсу через `?token=` из ссылки бота. Бот — часть Laravel (вебхук `TelegramWebhookController`), не отдельный сервис.
- **Курсы валют** парсятся отдельным пайплайном от кредитов/депозитов (свой Go-бинарник `cmd/rates`, свой cron); публикуются на `/kurs-valyut` и используются ботом для алертов.
- **API без rate limiting** — throttle-middleware на публичных эндпоинтах не настроен; учитывать при работе с формами/заявками.

## Вне рамок MVP

Классическая авторизация публичных пользователей (email/пароль) — есть только Telegram-based `/profile` для алертов по курсу, это не полноценный личный кабинет с историей заявок/избранным. Прочие категории продуктов (страхование, карты, переводы — ипотека теперь subcategory кредита, не отдельная категория), мобильное приложение, платёжная интеграция, webhook-интеграция с банками для заявок (только email).
