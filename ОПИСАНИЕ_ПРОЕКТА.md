# Sravni.tj — описание проекта (as-is)

**Дата среза:** 2026-08-10. Составлено по факту кода (роуты, миграции, контроллеры), не по ТЗ/PRD — те частично устарели, см. [ТЗ.md](ТЗ.md) §12 для истории решений.

---

## 1. Что это

Агрегатор банковских продуктов Таджикистана (аналог sravni.ru): каталог кредитов, депозитов и рассрочки от банков РТ, сравнение продуктов бок о бок, приём заявок (лидов) в банк по email, плюс отдельный блок — курсы валют банков с Telegram-ботом для алертов по курсу и ежедневные финансовые посты в Telegram-канал (§6.1).

---

## 2. Стек и монорепо

| Компонент | Технология | Назначение |
|---|---|---|
| `parser/` | Go | Три независимых бинарника: сбор продуктов, поиск источников, курсы валют |
| `backend/` | PHP / Laravel 13 (PHP 8.4) | REST API, приём заявок, админка, Telegram-бот (вебхук) |
| `frontend/` | Vue.js + Pinia + Vue I18n, SSR (Express) | Витрина, калькулятор, заявки, /profile, /admin (CSR) |
| БД | PostgreSQL | Общее хранилище для парсера и бэкенда |

Поток данных: Go-парсер пишет в PostgreSQL → Laravel читает и отдаёт REST API → Vue рендерит (SSR для публичных страниц, CSR для админки).

## 3. Публичная витрина (frontend)

Маршруты (`frontend/src/router/index.ts`), каждый с `/tj`-двойником кроме admin:

| Путь | Страница |
|---|---|
| `/` | Главная — топ кредитов/депозитов, лучший курс, CTA |
| `/credit`, `/deposit`, `/installment` | Каталог по категории — фильтры + сортировка + пагинация |
| `/product/:id` | Карточка продукта — тарифная сетка, калькулятор, документы, FAQ |
| `/bank/:id` | Карточка банка — продукты, отзывы, курсы |
| `/compare` | Сравнение 2–4 продуктов бок о бок (стейт в Pinia) |
| `/kurs-valyut` | Курсы валют всех банков + кнопка подписки на Telegram-алерты |
| `/otzyvy` | Форма отзыва о банке (премодерация) |
| `/profile` | Личный кабинет Telegram-подписчика — управление алертами по курсу (авторизация через `?token=` из бота) |

### Фильтры каталога
Валюта, вид продукта (subcategory), банк (мультиселект), сумма/срок/ставка (диапазоны), фичи (онлайн-оформление/без поручителя/капитализация/пополнение), спец.-флаг для аномальных кредитов. Банки/фичи/подкатегории применяются мгновенно; диапазоны — по кнопке «Применить»; «Сбросить» чистит всё.

### Калькулятор
Полностью на клиенте: аннуитет для кредита, простые/сложные проценты для депозита — не парсится, считается по параметрам продукта или введённым вручную.

### i18n
Два языка — `ru`/`tg` (код локали на фронте `tj`). Мультиязычные поля в БД — парами колонок `*_ru`/`*_tg` (не JSON), CHECK «хотя бы одно заполнено».

### SEO/GEO
SSR (Express + Vite SSR entry, `@unhead/vue/server`). Динамические `/robots.txt` и `/sitemap.xml` (БД-driven, сайтмап кеш 10 мин). JSON-LD: `Organization`+`WebSite` на главной, `FinancialProduct`+`FAQPage` на карточке продукта. `hreflang` ru/tj реципрокный + `x-default`, canonical на `sravni.tj`. Админка — CSR-only, без SEO (auth в localStorage, недоступна SSR).

## 4. Backend API (`backend/routes/api.php`)

Плоский `/api/*`, без версионирования. **Rate limiting не настроен** (throttle-middleware не найден).

**Публичные:**
- `GET /products/{credits|deposits|installments}` — каталог, `GET /products/{id}` — карточка
- `GET /banks`, `GET /banks/{id}`
- `GET /rates`, `GET /rates/best`
- `GET/POST /banks/{id}/reviews`
- `POST /leads`
- `POST /telegram/subscribe-init`, `POST /telegram/webhook` (секрет), `POST /internal/rates-notify` (internal-секрет, дёргает Go-парсер курсов)

**Профиль** (`auth:user`, Bearer `api_token`, регистрация только через Telegram): `GET/PATCH /profile`, `GET/POST /profile/alerts`, `DELETE /profile/alerts/{id}`.

**Админка** (`/api/admin/*`, guard `admin`): `POST login` (публично) → `auth:admin`: `GET me`, `POST logout`, `apiResource banks`, `GET banks/{id}/products`, `apiResource products except(index)` + `PATCH products/{id}/toggle`, `GET/DELETE leads`, `apiResource users except(show)`, `GET post-topics/preview`, `apiResource post-topics except(show)`, `GET finance-posts`, `POST finance-posts/from-source`.

Отдаёт только `products.status=active` с банком `status=active` (публичные эндпоинты).

## 5. Админ-панель

- Своя token-аутентификация (не Sanctum) — `admin_users.api_token`. Роли: `admin` (+ управление пользователями) | `editor`.
- Функционал: CRUD банков, CRUD продуктов + toggle статуса, просмотр/удаление лидов, CRUD пользователей (только admin).
- `locked_fields` у продукта (category/subcategory/features) — поле, закреплённое редактором вручную, парсер его больше не перезаписывает.
- **Вне админки** (только прямой доступ к БД): модерация отзывов, курсы валют.
- Frontend `/admin/*`: `LoginView`, `AdminLayout`, `BanksView`, `BankDetailView` (+ продукты банка), `LeadsView`, `UsersView`, `FinancePostsView` (CRUD generic-тем, превью расписания на 7 дней, история постов — см. §6.1).

## 6. Telegram-бот (курсы + алерты)

Часть Laravel-бэкенда (вебхук), не отдельный сервис — `TelegramWebhookController` + `TelegramService`/`RateDigestService`, секьюрити через `X-Telegram-Bot-Api-Secret-Token`.

Флоу подписки: витрина → `POST /telegram/subscribe-init` → одноразовый токен (Cache, TTL 15 мин) → `deep_link` `t.me/<bot>?start=<token>` → `/start` в боте создаёт/обновляет `users` (telegram_id + api_token) — **регистрация только через бота**. Дальше — `/profile` на витрине для управления подписками на алерты (`rate_alert_subscriptions`: валюта, buy/sell, above/below, порог).

Курсы валют парсятся **отдельным пайплайном** от кредитов/депозитов: свой Go-бинарник (`cmd/rates`), cron почасово в дневном окне, может идти без AI (детерминированный `rate_rule` json_path). После прогона — internal-webhook триггерит рассылку алертов.

### 6.1. Ежедневные посты в Telegram-канал

Отдельная от §6 интеграция (публикация в канал, не DM боту). Один artisan `posts:run-scheduler` (Railway-cron `telegram-posts`, `*/10 * * * *` — каждые 10 минут круглосуточно) совмещает генерацию и отправку — не два сервиса, т.к. Railway-крон разово поднимает контейнер на тик, постоянного процесса с внутренним шедулером нет.

На каждом тике: (1) если не раньше 04:00 UTC/09:00 Душанбе и сегодня ещё не генерировали (гейт по `finance_posts.generated_at`) — выбирает тип дня по дню недели (`PostTopicSelector::WEEKLY_PATTERN`): generic-тема (LRU по `post_topics`, антидубль-контекст — кусок предыдущего поста на ту же тему в промпте) / конкретный продукт (`ProductSpotlightSelector`, без повтора 30 дней) / снепшот курсов (`CurrencyRateSnapshotService`); текст — `LlmService` (первый LLM-клиент в Laravel, провайдер `openrouter`/`deepseek` через `AI_PROVIDER`/`AI_API_KEY`/`AI_MODEL` — те же имена, что у парсера); (2) отправляет все `finance_posts` со `status=pending` и `send_at <= now()` через `SendFinancePostJob::dispatch()` (синхронно, `QUEUE_CONNECTION=sync`, как `DispatchRateAlerts`).

Отправка «откладывается» на случайные 1–90 минут через `send_at`, без отдельной delayed-очереди/воркера. Канал — chat_id в `TELEGRAM_CHANNEL_ID`, без выбора в админке. Картинки не реализованы (TODO). История курсов (`bank_currency_rates`) хранит только последний снепшот — динамика за период не отдаётся, это отдельная нереализованная задача.

Отдельно — `kind='news'`: `POST /api/admin/finance-posts/from-source` (заголовок+текст новости от админа → LLM пересказывает своими словами → сразу `pending` со случайным `send_at`, без предпросмотра). Внеплановый, не участвует в `WEEKLY_PATTERN`, не блокирует обычный пост дня.

## 7. Парсер (Go, `parser/`)

Три бинарника: `cmd/discover` (поиск источников), `cmd/parser` (продукты), `cmd/rates` (курсы).

- Скрейперы (`internal/scrape/`): `direct` (HTTP GET + readability, дефолт), `firecrawl`, `browser` (свой headless Chrome/CDP) — выбор per-source, не глобальный.
- AI (`internal/extract/`): openrouter (дефолт в проде — `deepseek/deepseek-chat-v3.1:free`, т.е. **free-tier**, несмотря на задокументированную рекомендацию платной модели — стоит пересмотреть при нестабильном парсинге), + прямые gemini/qwen/deepseek.
- Cron (Railway `railway.json` / `railway.rates.json`): продукты — каждые 5 дней в 03:00 UTC (08:00 по Таджикистану, временно снижено с 2 дней из-за расхода AI-токенов — пересмотреть после настройки); курсы — каждые 2 часа с 08:00 до 18:00 по Таджикистану.
- Числовые поля валидируются на диапазон (ставка 0–100%, сумма>0) до записи — но **0% сейчас проходит валидацию как легитимное значение**, из-за чего часть продуктов в каталоге показывает «Ставка 0%» при том, что в текстовом описании указана реальная ставка (см. находку при QA-тестировании — вероятно AI не смог извлечь число и просел в 0 вместо null/pending).

| Таблица | Ключевое |
|---|---|
| `banks` | name_ru/tg, slug, status, is_partner, contact_email, website, phone, address_ru/tg, about_ru/tg, products_updated_at/rates_updated_at (когда парсер последний раз УСПЕШНО, >0 строк, обновил продукты/курсы; null = ни разу) |

| `products` | bank_id, source_url_id, category/subcategory, name/description_ru/tg, status, currency, rate_min/max, amount_min/max, term_min/max, features(jsonb), locked_fields, is_special |

| `bank_reviews` | bank_id, author_name, rating(1–5), body, consent, status(pending/approved/rejected) |
| `bank_currency_rates` | bank_id, currency, category(cash/transfer), buy/sell, rate_date |

| `rate_alert_subscriptions` | user_id, category, currency, op(buy/sell), direction(above/below), threshold, last_notified_value/at |
| `parser_runs` | метаданные парсинга — пишется только при `PARSER_DEBUG_LOG=true` |
| `post_topics` | title, prompt, is_active, last_used_at (LRU для generic-дней ежедневных постов, §6.1) |
| `finance_posts` | kind(generic/product/currency), post_topic_id, subject_type/subject_id, body, status(pending/sent/failed), generated_at, send_at, sent_at, telegram_message_id, error |

## 9. Известные проблемы на момент среза

- «Ставка 0%» на части продуктов каталога — вероятно AI-парсер не извлёк число, записал 0 вместо null; проходит валидацию (0 в диапазоне 0–100). Нужно решение: считать 0 подозрительным по умолчанию (кроме исламских installment-продуктов, где 0% легитимен) или фиксить на уровне AI-схемы/промпта.
- `/installment` пуст (0 продуктов) на момент QA — либо категория ещё не наполнена, либо источники не настроены.
- AI-провайдер парсера в проде — free-tier модель, вопреки внутренней рекомендации использовать платную (риск нестабильности: 429, обрезанный JSON).
- Rate limiting на публичном API не настроен.
